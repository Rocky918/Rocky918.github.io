SpaceDAO · 产品需求说明书

文档目标：定义组织创建、代币领取、提案投票与核验记录的页面规则、数据约束和验收条件。适用角色：产品、设计、前端、后端、合约开发与测试。

范围与用户路径

目标用户为组织创建者与成员；核验人员是需求中的任务角色，不代表已确认系统权限。

首页 → 创建 DAO → 基本信息 → 确认创建 → 新组织空空间 → 首页回访
首页 → 星舟社区 → 成员领取 / 项目分配 → 领取确认 → 核验记录
首页 → 星舟社区 提案 → 选择意见 → 确认投票 → 结果与记录

当前原型可操作：首页、两步创建、空组织、视角切换、领取、单次链下投票及核验筛选。

本轮不实现：真实身份认证、合约部署、链上投票提交、提案创建表单、社区发帖、邀请成员、收费、后台持久化与多人协作。它们的历史上线情况与此原型覆盖范围是两件事。

结果边界：历史领取转化率前后分母不同，不写增长幅度；看板商业化改进停留在方案和部分原型，未作为已上线需求纳入本轮。

页面需求与验收

“查看原型”进入对应页面；每个页面顶部可返回本条需求。验收标准描述预期行为。

HOME-01首页与组织入口

范围：首页组织列表、已有组织快捷入口、新组织回访。
用户目标：让成员快速进入组织，并找到个人领取与治理任务。

业务规则与当前实现

  • 默认展示星舟社区 示例卡片；当前会话新建组织追加到列表。
  • 进入星舟社区 打开代币分配；进入新组织打开其独立空空间。
  • 快捷任务始终标明星舟社区，不代表新组织待办。

流程与异常

  • 首页 → 创建 DAO → 新空间 → 返回首页 → 再次进入
  • 刷新／重置会清空新组织；原型没有跨设备或多人同步。

验收标准

编号条件 / 操作预期结果
AC-H01创建一个 DAO 后返回首页新组织出现；再次进入展示其名称和简介。
AC-H02从新空间点击星舟社区 的领取入口上下文明确切回星舟社区，不混入新组织数据。

实现边界

当前首页按已有组织、新建组织的顺序展示；真实成员权限与列表数据由服务端提供，原型使用本地数据。

DAO-01创建 DAO：基本信息

范围：组织名称、简介、类型与身份校验。
用户目标：帮助组织发起者建立协作空间；此步骤不代表完成链上组织部署。

业务规则与当前实现

  • 名称必填，去首尾空格后 2—40 个字符；简介必填，去首尾空格后 10—300 个字符。当前前端长度按 JavaScript 字符串长度处理；生产计数口径待统一。
  • 类型为社区协作、项目共建、学习研究、其他；默认社区协作。
  • 当前原型在会话范围内按完整名称比较，拒绝与星舟社区或已创建组织同名。
  • 进入确认步骤前需要关联成员身份；错误时保留输入，不创建记录。

流程与异常

  • 填写 → 前端校验 → 确认页；返回修改保留输入。
  • 从导航返回首页不会自动清除表单；刷新或成功创建后清空。

验收标准

编号条件 / 操作预期结果
AC-D01名称仅空格或简介不足 10 字符停留在表单并提示；没有新增组织。
AC-D02填写合法信息并进入确认后返回修改所有字段保留，可重新提交确认。
AC-D03断开成员身份后点击下一步提示关联身份，不进入确认。

实现边界

本原型按关联身份、会话内名称不重复、UTF-16 长度及字段上限进行校验；这些规则限定当前页面行为。

DAO-02确认创建与空空间

范围：确认页、创建成功、新组织空状态。
用户目标：在写入前核对信息，并区分组织创建与后续治理配置。

业务规则与当前实现

  • 确认页展示名称、简介、类型和创建身份；确认动作再次检查身份。
  • 当前确认创建仅写入页面内存，随后生成首页卡片并进入新空间。
  • 新空间不继承星舟社区 的讨论、提案、领取与核验数据。
  • 原型没有真实请求中的加载、网络失败和服务端重复创建状态；生产接入时须补充，不能把当前流程视为完整接口验收。

流程与异常

  • 确认 → 创建成功 → 空空间；返回修改 → 基本信息。
  • 生产建议：提交中禁用重复操作；失败保留输入；响应不确定时先查询结果再重试（未实现）。

验收标准

编号条件 / 操作预期结果
AC-D04确认页面断开身份再创建提示错误，组织列表不增加。
AC-D05成功创建后进入新空间名称和简介与输入一致；显示暂无提案、暂无代币分配。
AC-D06同一页面再次输入已有组织名称提示同名，不新增重复组织。

实现边界

本页创建仅生成内存中的组织空间，不部署合约；服务端去重、持久化与管理员权限不在当前实现范围内。

ASSET-01个人领取与项目视角

范围：成员金额、解锁计划、成员／项目视角切换。
用户目标：将成员领取任务前置，同时保留组织全局分配信息。

业务规则与当前实现

  • 已确认历史方向：展示已解锁、已领取、待领取金额及下一期解锁时间，支持成员／项目视角切换。
  • 12,000、8,000、4,000 UNIT 及下一期日期均为演示值；不作为真实分配记录。
  • 本原型金额关系为：已解锁 12,000 = 已领取 8,000 + 待领取 4,000。该关系用于当前样例，不作为所有合约的通用公式。
  • 项目比例为 50%／30%／20% 的静态样例，不代表历史代币模型。

流程与异常

  • 成员视角 ↔ 项目视角；切换不改变领取状态。
  • 数据加载、余额查询失败、未适配合约页面未实现，属于生产前补充范围。

验收标准

编号条件 / 操作预期结果
AC-A01切换成员及项目视角各自信息可见，个人领取状态不被重置。
AC-A02领取成功后返回成员视角金额、状态、按钮显示一致。

实现边界

当前采用整数 UNIT、固定业务日期及本地状态更新；未接入合约余额查询。

CLAIM-01领取确认与结果反馈

范围：领取确认、取消、失败、成功与记录联动。
用户目标：让成员理解领取是否完成，避免把提交当成功。

业务规则与当前实现

  • 未关联成员身份时阻止领取并提示。
  • 确认弹窗提供取消、模拟失败、模拟成功；取消和失败不改变金额。
  • 成功后已领取更新为 12,000、待领取归零；本期按钮禁用，并新增一条领取核验记录。
  • 原型没有真实签名、手续费、交易确认等待、回滚或重组处理。

流程与异常

  • 可领取 → 确认 → 取消／失败：返回可领取；成功：已领取。
  • 生产建议区分待签名、已提交、确认中、成功、失败；判定依据需链上与后端共同定义。

验收标准

编号条件 / 操作预期结果
AC-C01分别取消领取、模拟失败金额和核验列表不变化，可重试。
AC-C02模拟成功三个金额一致更新，按钮禁用，新增一条记录。
AC-C03已领取后再次操作不能重复领取；刷新为重置演示，不等于真实余额回退。

实现边界

当前由确认弹窗驱动成功或失败状态；链上最终确认、事件关联及余额对账属于合约接入范围。

VOTE-01提案投票与结果

范围：提案详情、意见选择、确认与结果展示。
用户目标：帮助成员理解提案、表达意见，并查看适用规则下的结果。

业务规则与当前实现

  • 历史已确认提案创建、链下／链上投票、基础权重与结果公示；本原型只演示链下单次投票。
  • 示例支持、反对、弃权三选一；未选择或身份未关联时阻止提交。
  • 确认后所选项加 1，禁用选项和提交按钮；新增链下核验记录。
  • 初始 12／3／1 为示例基线；百分比四舍五入，可能不严格合计 100%。
  • 治理代币周期分配及使用后不返还来自业务背景；不自动套用到本示例一人一票。

流程与异常

  • 未选择 → 选择 → 确认 → 返回修改／已确认。
  • 生产待补：提案未开始、已截止、资格不足、额度不足、重复请求、链上确认中。

验收标准

编号条件 / 操作预期结果
AC-V01不选择直接提交提示选择意见，无新增投票。
AC-V02选择支持并确认支持从 12 到 13，总票数从 16 到 17；记录增加，重复提交被禁用。
AC-V03确认弹窗返回修改不计票，仍可修改意见。

实现边界

当前规则为关联身份后单次链下投票，每次计 1 票；确认后不可再次提交。链上权重、提案创建和收益分配不在本原型实现范围内。

VERIFY-01记录筛选与核验详情

范围：模式、核验依据、状态筛选和记录详情。
用户目标：帮助定位数据不一致，区分链下记录与链上确认。

业务规则与当前实现

  • 展示记录编号、类型、核验依据、状态和详情。
  • 支持全部、已确认、确认中、异常筛选；筛选不改变记录。
  • 链下记录不要求链上交易；链上确认中记录不直接宣称为有效票。
  • 领取与投票的本地成功动作追加记录；查看详情不授予修改票数权限。

流程与异常

  • 全部记录 → 状态筛选 → 详情 → 关闭。
  • 筛选无结果时展示暂无匹配记录；真实分页、数据获取失败和自动重试未实现。

验收标准

编号条件 / 操作预期结果
AC-R01筛选确认中只显示确认中样例；返回全部后恢复完整列表。
AC-R02查看异常详情再关闭可见不一致说明，状态和票数不发生变化。

实现边界

当前记录只读，按编号关联本地操作，支持状态筛选；权限隔离、审计保留和异常处置服务不在当前实现范围内。

数据与开发协作约定

以下说明数据对象、约束与模块职责；接口路径和字段命名不在本文覆盖范围内。

对象建议数据与约束当前原型 / 接入前工作
组织daoId、名称、简介、类型、创建者身份；列表与详情使用同一稳定标识。当前仅内存对象，无持久 ID。后端需定义权限、唯一范围、去重及失败恢复。
成员领取组织、钱包、合约、代币、金额、解锁时间与查询时间。建议最小单位整数字符串，避免浮点误差。当前静态金额。链上与后端确认金额来源、精度、最终状态及对账规则。
提案与投票提案标识、模式、资格、权重依据、截止时点、选项、记录标识与状态。当前固定提案及计数。确认计票口径后，服务端或合约执行资格与权重校验。
核验记录组织、业务类型、业务记录标识、模式相关依据、状态、更新时间；链下依据与链上依据分开。当前虚构记录。定义关联键、分页、访问控制与异常处置，不默认允许人工改票。
通用错误区分未认证、无权限、字段错误、重复操作、网络失败与最终状态未确认。界面保留输入并提供可恢复路径；请求超时不等于业务失败，重试前查询或去重。

协作职责

产品确认边界与验收口径；设计补齐状态与信息层级；前端实现校验及反馈；后端负责持久化、权限及去重；链上开发确认合约语义与最终性；测试依据需求编号覆盖正常、异常与跨组织隔离。

数据观察建议

创建流程可观察进入、字段校验失败、确认、创建结果；领取和投票分别记录提交与最终确认。当前未接入埋点。转化指标必须写明统计窗口、分母、去重单位与最终成功依据，不能把页面点击当链上成功。
